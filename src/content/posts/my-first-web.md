## 关于我的第一个个人网站的制作过程

&emsp;&emsp;这次作业是做一个 weblog 记录专业课的学习过程。我本来可以找个模板改改就交，但我想知道那些“一键生成”背后到底发生了什么，所以决定从最传统的开始：手写让AI给我从最基础的开始写，不用框架、构建工具和npm之类的 。

## 初版：仅用HTML和CSS

&emsp;&emsp;一开始，我问了AI一个问题：“一个静态网站，是不是我每更新一篇文章，就要多敲一个HTML？”

&emsp;&emsp;显然答案是不必，于是他给了我三种方案。

| 维度                       | 手写 HTML                   | 数据 + JS 渲染         | 静态站点生成器               |
| -------------------------- | --------------------------- | ---------------------- | ---------------------------- |
| 你会 HTML 吗               | 必须会                      | 需要懂一点 DOM         | 基本不用                     |
| 新增一篇文章的成本         | 新建 1 个 HTML + 改首页链接 | 改 1 个数据文件        | 新建 1 个`.md`，跑一次构建 |
| 改一次版式（比如换导航栏） | 所有 HTML 逐个改            | 改 1 处                | 改 1 个模板                  |
| 内容是否天生利于 SEO       | 最好                        | 较弱（内容由 JS 生成） | 最好                         |
| 首屏速度                   | 最快                        | 需等 JS 执行完         | 最快                         |
| 引入的复杂度               | 最低                        | 低                     | 需要 Node 环境和构建命令     |
| 适合阶段                   | 3～5 篇以内、纯学习         | 想练 JS、不在乎 SEO    | 长期维护的真实博客           |

&emsp;&emsp;我的天！那我必须每个都尝尝😋

&emsp;&emsp;于是它拿出了第一版，确实很简陋，不过也能用。当我想试试加一篇测试文章时，发现不仅要自己手敲一篇HTML，还得去 `index.html` 加一大串东西。

**&emsp;&emsp;？这谁受得了**

&emsp;&emsp;在我的催促下，大鲸鱼火速产出第二版。

## 第二版：HMTL+CSS+JavaScript

&emsp;&emsp;这一版在外表上看起来和前一版没什么区别，所以我深入了她的内心（？）。

      "<h2>HTML 的角色：描述结构，不描述外观</h2>",
      "<p>HTML 的全称是 HyperText Markup Language，即超文本标记语言。它的职责只有一个：<strong>标记出内容的结构和含义</strong>——哪部分是标题、哪部分是段落、哪部分是导航。</p>",
      "<p>至于标题应该多大、什么颜色，那不是 HTML 的事，是 CSS 的事。</p>",

      "<p>以 <code><a href="目标地址">链接文字</a></code> 为例：<code>a</code> 是标签名，来自 anchor（锚点）；<code>href</code> 是属性名；引号里的是属性值；标签之间的文字是内容。</p>",
      "<p>有些标签没有内容和结束标签，称为空元素，例如 <code><img></code>、<code><br></code>、<code><meta></code>。它们写成自闭合形式：<code><img /></code>。</p>",
      "<h2>为什么语义化标签值得多打几个字母</h2>",
      "<p><code><header></code>、<code><nav></code>、<code><main></code>、<code><article></code>、<code><footer></code> 这些标签，和 <code><div></code> 在默认外观上几乎没有区别。那为什么还要用它们？</p>",
      "<ul><li><strong>可访问性</strong>：读屏软件可以据此提供「跳到主内容」「跳到导航」这类快捷操作。</li><li><strong>可维护性</strong>：半年后回看代码，一眼就知道哪块是什么。</li><li><strong>搜索引擎</strong>：虽然权重不高，但结构清晰总比一堆无名 div 好。</li></ul>",
      "<blockquote>一个简单的判断标准：能用语义标签表达清楚的地方，就不要用 div。div 是实在没有合适标签时的兜底选择。</blockquote>",
      "<h2>本站现在的 HTML 结构</h2>",
      "<p>页眉、导航、页脚仍然写在每一个 HTML 文件里，这一点和上一版没有区别。</p>",

      "<p>这是 S2 阶段的变化，也是后面要展开的话题——当页面由数据生成，HTML 文件就不再需要一篇一篇地复制了。</p>"
